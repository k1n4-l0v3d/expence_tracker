# Совместные счета — Дизайн

**Дата:** 2026-05-13  
**Сценарий:** Семья / пара ведут общий бюджет  
**Подход:** Вариант A — SharedAccount как отдельная сущность

---

## 1. База данных

### Новые таблицы

#### `shared_accounts`
| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER PK | |
| `name` | VARCHAR(100) | Название: «Семейный бюджет» |
| `created_by_user_id` | FK → users.id | Кто создал |
| `created_at` | DATETIME | |

#### `shared_account_members`
| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER PK | |
| `shared_account_id` | FK → shared_accounts.id | |
| `user_id` | FK → users.id | |
| `joined_at` | DATETIME | |

Уникальный индекс: `(shared_account_id, user_id)` — один пользователь не может быть дважды в одном счёте.

### Изменения в существующих таблицах

Добавляется nullable FK `shared_account_id` → `shared_accounts.id` в:
- `expenses`
- `incomes`
- `monthly_budgets`
- `savings_accounts`

Добавляется nullable FK `added_by_user_id` → `users.id` в:
- `expenses`
- `incomes`

**Правило:** `shared_account_id IS NULL` → личная запись; заполнен → запись общего счёта.

## 2. Переключение контекста

### Flask session

`session['active_shared_account_id']`:
- `None` — личный режим (по умолчанию)
- `<int>` — ID активного общего счёта

### Хелпер `get_active_context()`

Возвращает `('personal', current_user.id)` или `('shared', shared_account_id)`.  
Все существующие маршруты используют этот хелпер при фильтрации запросов к БД и при сохранении новых записей.

### Навбар — переключатель контекста

Выпадающий список рядом с именем пользователя:
```
[👤 Личный ▼]
  ✓ Личный
    Семейный бюджет
  + Создать общий счёт
```

### Визуальный индикатор

Когда активен общий счёт — цветной баннер вверху каждой страницы:  
`"Общий счёт: Семейный бюджет"` — постоянное напоминание об активном контексте.

## 3. Маршруты

| Маршрут | Метод | Действие |
|---|---|---|
| `/shared/create` | POST | Создать общий счёт |
| `/shared/<id>` | GET | Страница управления счётом |
| `/shared/<id>/invite` | POST | Пригласить по логину/email |
| `/shared/<id>/leave` | POST | Покинуть счёт |
| `/shared/switch/<id>` | GET | Переключить на общий счёт |
| `/shared/switch/personal` | GET | Переключить на личный режим |

### Страница управления `/shared/<id>`

- Название счёта
- Список участников: аватар, имя, дата вступления
- Форма приглашения (ввод логина или email существующего пользователя)
- Кнопка «Покинуть счёт»

### Списки расходов/доходов в общем режиме

Каждая запись отображает бейдж с именем пользователя который её добавил (`added_by_user_id`).

---

## 4. Контроль доступа

### Декоратор `shared_member_required`

Проверяет что `current_user` является участником `shared_account_id` из URL. Если нет — `abort(403)`.

Применяется ко всем маршрутам `/shared/<id>/*`.

### Права участников

Все участники имеют равные права: добавлять, редактировать, удалять записи в рамках общего счёта. Нет роли «владелец» с особыми правами.

---

## 5. Граничные случаи

| Ситуация | Поведение |
|---|---|
| Приглашение несуществующего логина/email | Flash-ошибка «Пользователь не найден» |
| Пользователь уже участник счёта | Flash-ошибка «Уже является участником» |
| Последний участник покидает счёт | Счёт и все его данные удаляются (cascade delete) |
| Пользователь удалён из системы | Его записи остаются, `added_by` показывает «Удалённый пользователь» |
| Прямой доступ к чужому счёту через URL | `403` через `shared_member_required` |
| Пользователь в общем режиме, сессия истекла | Возврат в личный режим после повторного входа |

---

## 6. Изоляция личных данных

- Личные записи пользователя (где `shared_account_id IS NULL`) остаются полностью изолированными.
- Участие в общем счёте никак не влияет на личный бюджет.
- AI-чат, PDF/Excel экспорт работают в контексте текущего активного счёта.

---

## 7. Что не входит в скоуп

- Уведомления о новых записях (push/email)
- История изменений / аудит-лог
- Несколько общих счетов одновременно (пользователь может состоять в нескольких, но активен только один)
- Роли владелец/участник (все равны)
